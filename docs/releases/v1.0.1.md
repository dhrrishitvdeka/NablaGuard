# NablaGuard v1.0.1

Patch release on the CPU-eager 1.0 API. Install this wheel instead of v1.0.0
if you use fuzz, advanced checks, NGF inspect, or `nabla replay`.

## Fixes

- Fuzz and `nabla check --trials N` keep `requires_grad`, so a wrong backward
  is reported instead of a silent pass.
- JVP, finite-difference, determinism, and user-supplied tensors share the
  stride-preserving leaf copy used by the base operator check.
- Deep-mode shadow comparison uses `complex128` for complex tensors.
- NGF inspect stays inside the artifact root (Windows drive/UNC paths, `..`,
  symlinks, junctions) and will not hash files above the inspection size cap.
- `nabla replay` requires `--i-trust-this-run` on every path.
- Replay of an already-restored checkpoint boundary is a pass.
- Capture environment and issue/event source paths redact home/user/host.
- Bisect errors on missing step metadata instead of treating gaps as good.
- Complex gradient norms, cosines, and cancellation use magnitude / real
  inner products.
- BugBench internal errors map to CLI exit 3.
- Ruff/mypy issues that failed CI are fixed; the matrix no longer fail-fasts.

## Validation

- 168 passed, 1 CUDA-conditional skip, ~87.5% line coverage (`fail_under = 85`)
- `ruff check .` and `mypy nablaguard` clean
- CI green on Python 3.10 / 3.11 / 3.12

## Compatibility

Unchanged from 1.0.0: CPU eager is the supported baseline. CUDA, AMP,
`torch.compile`, DDP/FSDP, Triton internals, and untrusted checkpoints remain
experimental or unsupported. See [compatibility](../compatibility.md).
