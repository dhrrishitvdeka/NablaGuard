# Failure minimization research log

## Problem

A large failing tensor case is costly to understand and preserve as a regression
test. The tool must reduce it without changing the definition of failure.

## Existing mechanisms

Property-testing libraries shrink values generated by their own strategies.
PyTorch exposes views and dtype conversion, but no tensor-operator failure
shrinker.

## Possible approaches

Delta-debug tensor dimensions and values, integrate a general property-testing
engine, or search concrete tensor recipes rather than raw storage.

## Experiments

NablaGuard re-executes the original candidate/reference/property predicate for
every proposed recipe. A controlled failure at last-dimension width eight
shrinks from `[64, 13, 17]` through dimension deletion and landmark sizes to
`[8]`.

## Results and decision

Version 0.2 uses a deterministic, budgeted greedy recipe shrinker. It attempts
dimension removal, smaller boundary dimensions, contiguous layout, simpler
distributions, and simpler floating dtypes. Artifacts retain both original and
minimal-known inputs.

## Limitations

Greedy order can miss a smaller failure requiring two simultaneous changes.
Regenerated values preserve the seed but shape changes alter the RNG stream.
The result is “minimal known,” never “minimal.” Raw-value chunk deletion and
stride-specific delta debugging remain future work.
